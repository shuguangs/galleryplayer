# 🎬 GalleryPlayer（媒体播放器）

> Windows 平台本地图片 / 视频浏览播放器。交互参照 Telegram 的内嵌播放器：一个文件夹里的图片和视频混在同一个列表里，滚轮就能一个个翻过去。

## ✨ 特性一览

- **播放内核**：libmpv（内含 FFmpeg），H.264 / HEVC / AV1 / VP9 以及 mp4、mkv、avi、wmv、flv、ts、rmvb 等容器直接播，NVIDIA / Intel / AMD 显卡自动硬解。
- **图片解码**：Qt 原生插件 + Pillow，含 HEIC / AVIF / JXL / 动画 WebP / APNG。
- **完全便携**：所有配置、缩略图缓存、播放进度都写在程序目录的 `userdata/` 下，不碰注册表，不写 AppData。整个文件夹拷到别的机器直接能用。
- **网络位置可用**：UNC 路径（`\\NAS\影视`）和映射网络驱动器都能直接浏览播放，识别到网络位置后自动把缓冲从 32 MB 提到 192 MB、预读从 5 秒提到 30 秒，并把后台抽帧串行化，避免多个任务抢同一条链路。
- **三种浏览视图**：网格 / 瀑布流 / 详情列表，视频封面自动抽帧缓存。
- **沉浸式查看器**：深色界面、自动淡出控制条、进度条悬停缩略图、断点续播、字幕 / 音轨切换。
- **播放列表面板**：播放列表 + 专辑收藏 + 浏览器三合一停靠面板。

打包后约 247 MB（其中 libmpv 自带的 FFmpeg 占 112 MB）。实测内存占用：

| 场景 | 占用 |
| --- | --- |
| 只浏览图片（缩略图已缓存，libmpv 完全不加载） | 约 90 MB |
| 浏览含视频的文件夹（后台抽帧中） | 约 340 MB |
| 播放 1080p 视频 | 约 430–560 MB，其中约 170 MB 是显卡 OpenGL 驱动本身占用 |
| 浏览 400 张图片的文件夹 | 峰值约 290 MB，不随文件数继续增长 |

两处刻意的约束：缩略图内存缓存有 200 张硬上限（LRU 淘汰，超出后从磁盘小 JPEG 重读，很快）；后台抽帧用的 libmpv 实例每个约 55 MB，空闲 15–25 秒后自动释放，需要时再重建。

## 🚀 快速开始

### 打包后的免安装版

解压后双击 `媒体播放器.exe`。`安装运行环境.bat` 会自动检查 / 安装 Microsoft Visual C++ 运行库（视频解码器已内置在 `vendor\libmpv-2.dll` 中，无需另装解码包）。

### 从源码运行

```bash
pip install -r requirements.txt
```

`vendor/libmpv-2.dll` 必须存在（约 112 MB）。若缺失，从 <https://github.com/shinchiro/mpv-winbuild-cmake/releases> 下载 `mpv-dev-x86_64-*.7z`，解压后把 `libmpv-2.dll` 放进 `vendor/`。然后：

```bash
python main.py
```

也可以带参数直接打开：`python main.py "D:\某个文件夹"` 或 `python main.py "D:\某个视频.mkv"`。

### 自己打包

```bash
python build.py
```

产物在 `dist/媒体播放器/`。可选参数 `python build.py complete` 可指定输出目录。

## 🖥️ 界面

### 浏览

启动后是空白欢迎页，不会自动打开上次的目录；页面上列出最近打开过的文件夹，点一下即进（已失效的目录会自动从列表里剔除）。

左侧目录树，中间三种视图，底部状态栏显示数量统计。

| 视图 | 说明 |
| --- | --- |
| **网格** | 等大 4:3 瓦片，封面裁切填满，视频右下角显示时长 |
| **瀑布流** | 按素材真实宽高比排列，竖屏横屏混排不变形 |
| **详情列表** | 名称 / 类型 / 大小 / 分辨率 / 时长 / 修改时间，点列头排序 |

视频封面自动从影片 18% 处抽帧，连同时长、分辨率一起缓存，第二次打开同一文件夹是瞬时的。

**目录扫描**：按层遍历（广度优先），先读完你点开的文件夹本身，再整层子文件夹并发读取 —— 本地 6 线程、网络位置 16 线程。本地 SSD 实测，739 个文件夹 / 4272 个文件：首次冷扫描 **160 ms**（并发），缓存出列表 50 ms（零读盘），后台增量核对 **113 ms**。2.1 万文件的树打开一次的最长卡顿从 ~7 s 降到 **~0.3 s**（缓存命中时无卡顿）。

**目录缓存**：每个目录连同修改时间、文件表、子目录表缓存在 `userdata/dircache.json`。再次打开时先零 I/O 画出列表（状态栏显示「正在核对…」），再后台增量核对，只有修改时间真的变了的目录才重新读盘。新增和删除文件都能被检出，按 `F5` 强制全量重扫。

**排序**：名称（自然排序，`第2集` 排在 `第10集` 前面）、修改时间、文件大小、时长、随机、自定义（面板里手动拖拽排序后自动切到自定义并持久保存）。
**筛选**：全部 / 仅图片 / 仅视频，外加文件名搜索。
**含子文件夹**：打开开关后把所有子目录的媒体平铺进同一个列表。也可以直接把文件夹或单个文件拖进窗口。

**右键菜单**：打开、用默认程序打开、在资源管理器中显示、复制完整路径 / 文件名、重命名、删除到回收站（`SHFileOperationW` + `FOF_ALLOWUNDO`，可原样还原）；点空白处是「打开所在文件夹」和「重新扫描」。删除前会先问一次，调不动回收站时宁可不删也不会直接抹掉。

### 查看器

深色沉浸式窗口，顶栏显示文件名、分辨率、编码、是否硬解、文件大小和序号；控制条和顶栏在鼠标静止约 2.6 秒后自动淡出，动一下就回来。

**滚轮永远是切换上一个 / 下一个**（和 Telegram 一致）。缩放和音量交给 `Ctrl+滚轮`。画面上的三个圆钮（播放 / 暂停，上一个 / 下一个）与顶栏同进同退，尺寸按窗口短边算并硬性卡在四分之一以下。

**进度条**：鼠标悬停弹出该时间点的画面缩略图，帧是实时抽的（约 150 ms），按 5 秒分桶缓存，来回拖不重复解码。已缓冲区间显示为较亮的一段。

**字幕**：自动加载同名 `.srt` / `.ass`（模糊匹配，`影片.chs.ass` 也认），内封字幕可切换，支持字号增减和 ±0.1 秒延迟微调，也能手动载入外挂字幕。ASS 特效字幕由 libass 完整渲染。

**断点续播**：时长超过 1 分钟、已看过 15 秒以上且离结尾还有 15 秒以上的视频记住进度，下次从断点继续并提示一次；看完自动清除记录。音量、倍速、视图模式、排序方式、窗口位置同样会被记住。

#### 右侧播放列表面板

按 `Tab` 开合（仿 PotPlayer 停靠面板）。展开时视频区自动让位，拖动左边缘改宽度（210–640 px），宽度、展开状态、标签页、行样式都会记住。

| 标签页 | 内容 |
| --- | --- |
| **播放列表** | 当前文件夹完整列表，和主窗口实时同步。正在播的项蓝底 + 左侧蓝条标记，自动滚动到可见位置 |
| **专辑** | 自建跨文件夹收藏，持久保存在 `userdata/albums.json`，支持重命名 / 清理失效项 / 删除 |
| **浏览器** | 目录树，和主窗口共用同一个模型。点文件夹就地换片，正在播放的不会被打断 |

行样式两种：**缩略图行**（54 px，小封面 + 文件名 + 时长·分辨率·大小）和**紧凑行**（26 px，几百集一屏看下很多）。列表支持拖拽排序、多选移动 / 移除、搜索过滤，右键有「添加到专辑」「用默认程序打开」「在资源管理器中显示」等操作。

**循环模式**按 `L` 循环切换：不循环 → 列表循环 → 单个循环 → 随机播放。「连放」单独控制是否自动接下一个。

## ⚙️ 实现要点

- 视频用 mpv 的 **render API** 渲染进 `QOpenGLWidget`，而不是把窗口句柄交给 mpv。Qt 6 会把 `QOpenGLWidget` 合成进窗口的后备缓冲，所以控制条这类普通 Qt 控件能正常半透明叠在画面上，没有原生子窗口的遮挡问题。
- 缩略图和进度条预览都用**常驻的无窗口 libmpv 实例**（`vo=null` + `screenshot-raw`）抽帧，因此不需要外部 `ffmpeg.exe`。每个工作线程复用自己的实例，避免反复初始化。
- 退出时会显式注销 mpv 的属性观察者、在 GL 上下文 current 的状态下释放 render context、并终止所有后台 libmpv 实例——这三步缺任何一步都会在进程退出时产生访问违例。
- 启动时不加载 libmpv、不构造查看器、不建详情表格，全部按需创建。只浏览已缓存的图片文件夹时 libmpv 根本不会被载入。
- 排序 key（自然排序、缩略图 SHA-1 缓存键）只在扫描线程顺手算一次，主线程一分钱不出；网格视图几何位置由序号直接算出，命中测试从遍历全表变成算术。

## 🐛 修掉的几个坑（都有回归测试）

- **抽帧实例复用后必须先解除暂停**。`open()` 抓完帧会把实例留在暂停态，而 `wait_until_playing()` 等的是 `core-idle` 变假——暂停的核心永远不会让它变假。结果是一个抽帧实例处理的第二个及以后视频全部 20 秒超时，表现为「文件夹里每隔一个视频就没有缩略图」。
- **缩略图缓存和元数据缓存会各自漂移**。缩略图 JPEG 还在、元数据条目没了的时候，旧代码直接返回图片，时长和分辨率就永远空着。现在会补一次轻量探测。
- **`MpvRenderContext.update_cb = None` 是有害的**。python-mpv 会把值包进 `lambda: func()` 再重新注册，赋 `None` 等于装了一个下一帧必然抛异常的回调。要用一个空函数。
- **停止标志是模块级的、且不会自动复位**。同一进程里再建一个 `ThumbnailCache` 会因为上一个的 `shutdown()` 留下的标志而静默丢弃所有任务。
- **`QThreadPool` 会在 `run()` 返回后删掉 QRunnable**，连带它自己持有的 QObject——排队中的信号还没送到 GUI 线程就被丢了，表现为扫描结果偶尔完全不出现。信号发射器必须由窗口持有。
